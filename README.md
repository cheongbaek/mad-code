# 자작 자율주행 전기차 제어 코드 정리

## 1. 차량 하드웨어 개요

- **제어보드** : Arduino Mega 2560 (모든 코드 공통)
- **배터리** : 58V (구동용). 아두이노/로직 측 12V는 별도 SMPS를 통해 공급
- **주행(인휠모터)**
  - 인휠모터 2개, 양 뒷바퀴에 1개씩 장착
  - 모터컨트롤러(KLS7275H) 2개, 모터 1개당 컨트롤러 1개
  - PWM 신호는 아두이노에서 양쪽 컨트롤러에 동시에 분배 (같은 PWM을 공유)
  - 모터 : QSWP72V5000W(QS260 계열), 16극쌍(=32극) — 허브모터 직결 구동(감속기 없음), 홀센서 위상각 120°, 무부하 최대 1320RPM (제조사 판매처 스펙 확인, 2026-07-13)
  - 타이어 : 175/60R13
  - 각 모터컨트롤러에서 나오는 홀센서 3개 신호를 SN74HC86N(XOR 게이트)으로 합산 → 컨트롤러당 합산 신호 1개
  - 좌/우 각 컨트롤러의 합산 신호가 아두이노 **2번(왼쪽)**, **3번(오른쪽)** 핀(인터럽트)에 각각 입력됨
  - 현재는 **2번 핀(왼쪽 모터)을 PID 속도 피드백으로 사용**, 3번 핀(오른쪽)은 모니터링 전용 (0708 실차 테스트에서 확정)
  - **차후 계획** : 좌/우 모터의 PWM 특성이 일부 달라, 공통으로 물려 있는 PWM 배선을 분리하고 모터별 개별 PID 제어로 전환 예정
- **조향**
  - DC모터 + 그와 맞물린 가변저항(포텐셔미터)으로 위치 제어
  - 모터드라이버 : **MD20A** (VNH2SP30 기반 2채널 DC모터 드라이버)
    - 채널당 연속 20A(순간 30A), 동작전압 5~30V, PWM+DIR 방식 제어
    - 본 프로젝트에서는 조향용으로 1채널만 사용 : DIR = 22번 핀, PWM = 6번 핀
    - DIR 핀 레벨로 회전방향, PWM 듀티로 회전속도 결정
  - `dc_0701_potential.ino`로 좌/우 끝값을 먼저 측정 → 안전 구동범위 산출
  - `dc_0701_dirtest.ino`로 DIR 핀 레벨과 실제 회전방향(좌/우)이 소프트웨어 정의와 일치하는지 확인
- **제동(브레이크)**
  - 인휠모터와 별개인 리니어모터가 브레이크 페달을 직접 밟는 구조
  - 페달에도 가변저항이 있어 얼마나 밟혔는지 감지 (별도)
  - **현재 리니어모터는 장비 미준비 상태 → 코드에 자리만 확보**
- **E-stop**
  - 40번 핀에 연결, 별도 장치가 스위치를 제어
  - **40번 핀이 단락(LOW)되면 e-stop 발동**으로 판단
  - 리니어모터와 마찬가지로 관련 하드웨어는 아직 미준비 → 코드에 자리만 확보

제어 주기: `kasa_0708_together.ino`는 인휠/조향/브레이크 제어 루프가 **20ms 공통 주기(`CONTROL_WINDOW_MS`)를 공유**한다 (실차 인휠 튜닝이 20ms 기준으로 검증됨. 텔레메트리 출력만 50ms). `iw_0708_pidtuning.ino`와 `dc_0702_pd.ino`도 20ms로 통일 (조향 PD게인을 kasa와 그대로 호환하기 위함). 게인·FF는 창 크기에 종속되므로 주기를 바꾸면 재튜닝이 필요하다. 구형 테스트 코드(`iw_0707_*`)만 50ms 기준으로 남아 있다. (`dc_0701_potential.ino`는 제어가 아닌 단순 모니터링 코드이므로 규칙 제외)

**버전 관리 방침** : 테스트 코드는 파일명의 날짜 숫자(`0707`, `0708`, ...)를 올려가며 새 파일로 만든다. 이전 날짜 파일은 그 시점의 코드를 보존하는 스냅샷으로 남긴다.

## 2. 공통 코딩 규칙 (`dc_0701_potential.ino` 제외)

- **`delay()`/`micros()` 지양, `millis()` 지향** : 정확한 시간 계산을 위해 모든 시간 지연/주기 판단은 `millis()` 기반 상태머신으로 구현한다. (`dc_0701_potential.ino`는 단순 모니터링 코드라 예외)
- **홀센서 인터럽트는 `CHANGE` 모드로 수신** : 펄스 수를 2배로 증폭하기 위함 (`RISING`/`FALLING` 단독 사용 금지)
- **MCU는 항상 Arduino Mega 2560 사용**
- **12V 전원은 배터리(58V)와 별도의 SMPS를 통해 공급**

## 4. `iw_0707_pwm2pulse.ino` 출력 형식

시리얼로 PWM(0~255)을 입력받아 그대로 출력하고, 50ms 주기로 아래 형식을 출력한다.

```
(pwm) (2번펄스) (3번펄스) (합산펄스)
```

- `2번펄스`, `3번펄스` : 각 주기(50ms) 동안 해당 핀에서 카운트된 펄스 수
- `합산펄스` : `2번펄스 + 3번펄스`

이 코드로 좌/우 모터컨트롤러 합산신호가 정상적으로 들어오는지, PWM 대비 펄스 응답이 어떤지를 먼저 확인한다.

## 5. `dc_0701_dirtest.ino` 방향 확인

- 소프트웨어가 정의한 "왼쪽(DIR_CW)"/"오른쪽(DIR_CCW)" 방향과 실제 모터 설치 방향이 일치하는지 확인하는 코드
- `delay()` 없이 `millis()` 기반 상태머신(`T_LEFT → T_GAP → T_RIGHT → T_DONE`)으로 동작: 왼쪽 0.5초 회전 → 관성 정지 대기 0.3초 → 오른쪽 0.5초 회전 → 종료(`T_DONE` 상태에서 정지 유지)
- PWM 값(`TEST_PWM`)은 실측 후 100으로 조정됨 (최초에는 `kasa_0708_together.ino`의 `STEER_MIN_PWM`을 참고값으로 사용했으나, 실제로 반응하는 수준에 맞춰 값을 올림)
- 실제로 왼쪽 → 오른쪽 순으로 돌지 않으면 `DC_DIR_PIN` 배선 또는 `DIR_CW`/`DIR_CCW` 정의(및 `kasa_example_control.py`의 `invert` 플래그)를 재확인해야 함

## 6. `dc_0702_pd.ino` PD 위치제어

- 조향 DC모터에 PD 위치제어를 접목하는 테스트 코드. 핀 구성과 제어 구조는 `kasa_0708_together.ino`의 조향부를 참고했으며, 게인(`KP_S`, `KD_S`)과 상한/하한 PWM(`STEER_MIN_PWM`, `STEER_MAX_PWM`), 안전 관련 값들을 모두 파일 상단에 두어 조절 가능하게 함
- **입력** : 시리얼로 목표각도(정수, `-40 ~ 40`) 한 줄 입력
  - `-40`/`+40`은 실측 좌/우 하드 리밋(raw, `RAW_LEFT_LIMIT`/`RAW_RIGHT_LIMIT`, `dc_0701_potential.ino`로 측정한 값으로 교체 필요)보다 `SAFETY_MARGIN`(5)만큼 안쪽으로 매핑됨
  - 범위 밖 값/숫자가 아닌 입력은 무시(별도 e-stop 없음, 조향 단독 테스트 코드)
- **하드 리밋 페일세이프** : 현재 raw값이 실측 하드 리밋(`RAW_LEFT_LIMIT`/`RAW_RIGHT_LIMIT`)에 도달하면 PD 계산과 무관하게 즉시 PWM 0
- **도달 판정** : `|오차| <= STEER_TOLERANCE`(3)가 `SETTLE_MS`(0.5초) 이상 연속으로 유지되면 도달로 판정 → 모터 정지 후 대기 상태(`ST_SETTLED`)로 전환
- **대기 상태** : 대기 상태에서는 가변저항 값이 바뀌어도 무시하고 정지를 유지하며, 새로운 각도값이 시리얼로 입력될 때만 제어를 재개함(`ST_ACTIVE`로 전환)

## 7. `iw_0707_pidtuning.ino` 속도 피드백 (구버전 스냅샷)

- 속도 피드백으로 3번 핀 펄스만 사용 (2번 핀 인터럽트 미연결), 제어주기 50ms, 게인 kp=2.0 / ki=0.2 / kd=1.2
- anti-windup은 "출력 포화 시 적분 누적 중단 + pwm 2회 계산" 방식, 미분은 오차 기반(`err - lastErr`)
- **실차 테스트에서 왼쪽 모터 이상폭주 발생** : PWM은 양쪽 컨트롤러에 공통 분배되는데 피드백은 오른쪽(3번 핀)만 보므로, 왼쪽 모터는 사실상 개루프 상태였던 것이 원인으로 추정됨 → `iw_0708_pidtuning.ino`에서 개선

## 8. `iw_0708_pidtuning.ino` 속도 피드백 (튜닝 완료 / 스냅샷)

0707 버전의 왼쪽 모터 이상폭주를 억제하고 튜닝을 완료한 버전. **결과는 `kasa_0708_together.ino`의 인휠 PID에 반영 완료.** 0707 대비 변경점:

- **피드백 소스 변경 (핵심)** : 2번(왼쪽, `encCountL`)/3번(오른쪽, `encCountR`) 핀을 각각 카운트하고, **PID 제어는 왼쪽(2번 핀) 펄스를 사용**. 3번은 모니터링 전용. 폭주하던 왼쪽 모터 자신의 펄스로 루프를 닫은 것이 폭주 억제의 주요 원인
- **제어주기 20ms**. 주의: 20ms 창의 펄스 수는 50ms 창의 40%이므로 여기서 잡은 게인을 50ms 코드에 그대로 이식하면 안 됨
- **미분항** : 측정값 기준(`-(speed - lastSpeed)`, derivative on measurement) — 목표값 계단 변경 시 미분 킥 없음
- **줄 단위 시리얼 파싱** : `parseInt()`의 CRLF/타임아웃 문제(target이 제멋대로 0으로 리셋)를 줄 버퍼 + 숫자 검증 방식으로 해결

### 실차 튜닝 경과 요약

1. 순수 P(kp=2)로 시작 → 출력이 데드존(~60 PWM) 아래에 갇혀 저속 목표에서 기동 불가 확인
2. **피드포워드 도입** : 실측 정적 맵(데드존 ≈60 PWM, 25펄스 ≈ 220 PWM) 기반 `ff = 60 + 6.4×target`. PID는 잔차 보정만 담당
3. **anti-windup 개선** : "출력이 포화된 방향으로는 적분 중단" (하강 스텝에서 −I_MAX까지 쌓인 적분 빚이 언더슛·재가속(엑셀 밟기) 리밋사이클을 만들던 문제 해결) + `±I_MAX`(100) 클램프 병행
4. **목표값 변경 시 적분 리셋**
5. 최종 게인 **kp=20 / ki=2 / kd=2** 에서 만족스러운 응답 확인

### 남은 개선 아이디어 (미적용)

- 목표 20 부근 상승 스텝에서 약간의 오버슛 잔존 (원인: FF가 커서 P의 포화 탈출이 목표 직전(3.3펄스 전)이고, 모터 상한(25)까지 달릴 여지가 남는 구간 + FF 선형 근사가 20에서 ~+20 PWM 과대) → 개선안: 목표값 램프(slew-rate limiter), kp 축소(8~10), FF 구간별 테이블화
- **좌/우 모터 개별 PID (차후 계획)** : 좌/우 모터의 PWM 특성이 일부 달라, 현재 공통으로 물려 있는 PWM 배선을 분리하고 모터별로 독립 PID를 돌려야 할 것으로 예상. 배선 분리 작업 이후 진행

## 9. `kasa_0708_together.ino` 통합 프로토콜

### 입력 (PC → 아두이노)

한 줄에 정수 3개를 공백으로 구분하여 전송 (개행으로 종료):

```
<주행목표값> <조향각도> <브레이크강도>
```

예) `32 -20 5`

- **주행목표값** : 인휠모터 목표 속도(펄스/주기). 0 이상 정수로 처리(음수는 0으로 clamp)
- **조향각도** : 도(degree) 단위, `-30 ~ +30` 범위로 clamp 후 `dc_0701_potential.ino`로 측정한 좌/우 끝값(raw)에 매핑되어 조향 목표 위치로 사용됨
  - 매핑 상수(`STEER_POT_LEFT`, `STEER_POT_RIGHT`, `STEER_ANGLE_MAX`)는 `kasa_example_control.py`의 기존 보정값(L=944, R=645, angle=±30)을 기본값으로 넣어두었으며, `dc_0701_potential.ino`로 재측정 시 코드 상단에서 갱신 필요
- **브레이크강도** : `0 ~ 255` 범위로 clamp. 리니어모터 미장착 상태라 실제 출력은 없고 값만 기록됨(`brake_output`)

### 인휠 PID (0708 튜닝 완료본 반영)

- 왼쪽 모터(2번 핀) 펄스로 루프를 닫음. 3번 핀(오른쪽)은 모니터링 전용
- 피드포워드 `ff = FF_DEADZONE(60) + FF_GAIN(6.4) × wheelREF` + PID 보정
- 포화 방향 적분 중단(anti-windup) + `±I_MAX`(100) 클램프, 측정값 기준 미분, 목표값 변경 시 적분 리셋
- 게인 kp=20 / ki=2 / kd=2, **인휠/조향/브레이크 제어 루프 모두 20ms 공통 주기(`CONTROL_WINDOW_MS`) 공유** (튜닝 검증 주기. 텔레메트리 출력만 50ms)
- E-stop 발동 중에는 적분·펄스 카운터를 초기화해 해제 후 잔재 없이 재개

### 출력 (아두이노 → PC)

50ms 주기로 아래 형식을 출력:

```
(2번펄스) (3번펄스)
```

- `2번펄스` : 왼쪽 모터 펄스 (20ms 창 기준, PID 피드백에 사용되는 값)
- `3번펄스` : 오른쪽 모터 펄스 (20ms 창 기준, 모니터링용)

### E-stop 조건 (아래 중 하나라도 충족 시 발동)

1. 40번 핀 단락 (LOW)
2. 입력 형식 오류 (정수 3개 공백 구분 형식이 아닌 경우 — 개수 불일치, 숫자가 아닌 토큰 포함 등)
3. 입력이 5초 이상 들어오지 않음

### E-stop 동작

- 조향(DC)모터 PWM = 0
- 인휠모터 PWM = 0
- 리니어(브레이크)모터 최고출력으로 구동 (미장착 상태이므로 실제 `analogWrite`는 주석 처리, 로직과 자리만 준비됨)
- 출력 펄스값을 `999 999`로 강제 표시 (실제 펄스 대신 `pulse2_out`, `pulse3_out` 변수에 999를 대입)

## 10. 2보드 분리 아키텍처 (`kasa_0713_A/B.ino`, 2026-07-13~)

### 배경

`kasa_0712_none.ino`까지는 인휠 PID/주행펄스 + 조향/제동을 아두이노 1대에서 처리했으나, 이후 **인휠모터 PID + 주행펄스(A보드)** / **조향 + 제동(B보드)** 두 대로 분리하기로 함. 두 보드는 서로 통신하지 않고 각자 독립적으로 동작한다.

### 핀 배정

- **A보드** (`kasa_0713_A.ino`) : 10(인휠 PWM), 20/21(홀센서), 13(E-stop)
- **B보드** (`kasa_0713_B.ino`) : 6/7(DC 조향 DIR/PWM), 8/9(리니어 브레이크 DIR/PWM), 13(E-stop)

### E-stop (양 보드 공통, 독립 판정)

- 스위치 AK-C211008의 NC 접점 2개를 **직렬** 연결: `아두이노GND ― COM2/NC2 ― COM1/NC1 ― 13번`
- 이 13번 라인을 **A보드·B보드 양쪽에 병렬로 연결**, 각 보드가 INPUT_PULLUP으로 독립 감지(500ms 연속 개방 시 확정 디바운스) + 자기 시리얼 라인 기준 5초 무입력 타임아웃
- 두 보드는 서로 통신 없이 각자 감지 시 자기 PWM만 정지하고 `STOP` 출력 → **한쪽 보드만 감지해도 그 보드는 반드시 정지**하는 페일세이프 구조
- A·B 보드는 GND가 공통이어야 함(별도 전원이면 GND끼리 연결 필요)
- ROS2(`walker_k` 노드)는 두 시리얼 포트 중 **한쪽에서라도** `STOP` 수신 시 전체 정지로 처리(OR)

### 시리얼 프로토콜 (상세는 `kasa_0713_protocol.md`)

- A·B는 PC(ROS2)와 **각각 별도의 USB/시리얼 포트**로 연결 (115200 baud)
- A입력: 주행목표펄스 정수 1개. A출력: `S,<21번펄스>,<20번펄스>` (50ms 주기)
- B입력: `<조향각>,<브레이크>` 콤마 2개. B출력: `P,<조향각환산값>` (가변저항 미장착 상태라 현재 항상 `P,0` 고정, 추후 ADC 장착 시 교체)
- 양쪽 모두 E-stop 중엔 `STOP` 출력 (접두어 없음)

### 인휠 PID 튜닝 경과 (`iw_0712_pid.ino`)

1. **FF 테이블 실측 재보정** : `iw_0709_pwm2pulse.ino`로 PWM 60~170 스윕 실측 → 기존 테이블(펄스 13 이상 구간)이 실측과 크게 어긋나 있어 실측치로 전면 교체
2. **오버슈트 원인 진단** : 목표펄스 진입 시 pwm이 FF+P만으로 곧바로 최대치 근처까지 치솟아 정지 마찰/제동 수단 없는 인휠모터에 과도한 관성이 붙는 것이 원인으로 확인
3. **대응** : PWM 슬루레이트 제한(사이클당 +4, 하강은 무제한), 조건부 적분 누적(|오차| < 4일 때만 적분), kp를 1.0 → 0.4로 완화, 최종 적분 기여를 ki 값과 무관하게 ±40 pwm로 클램프
4. **확정 게인** : `kp=0.4 / ki=0.03(±40 클램프) / kd=0.2`, `PWM_SLEW_MAX=4`, `I_ACCUM_ERR_MAX=4` — target 5, 15 양쪽에서 오버슈트 없이 수렴 확인(2026-07-13 실차 테스트)

### 참고: 목표펄스 → 차량속도 환산

- 홀신호 2개를 XOR 합산(120° 위상차) → 전기적 1회전당 4엣지 × 16극쌍 = **바퀴 1회전당 64펄스**(PPR), 직결 구동(감속기 없음) 기준
- 목표펄스 15(/20ms 창) → 750펄스/초 → 703RPM → 175/60R13 타이어(외경 540.2mm) 기준 **약 71.6km/h**
